01 Motivation for Autoencoder Slide 2/11
왜 Autoencoder인가?
  • 고차원 데이터를 bottleneck을 통해 압축된 잠재 표현(latent representation)으로 변환
  • 잠재 코드(latent code)는 단순 압축이 아니라 정보적이고 유용한 표현
  • 입력의 가장 두드러진 구조를 보존하면서 불필요한 변동은 제거
  • 정보이론적 관점: 재구성에 필수적인 정보를 유지하면서 최대한 압축된 표현을 추구
  • 데이터 마이닝 관점: 복잡한 고차원 데이터 안에 숨겨진 저차원 구조를 발견
  • 강건한 학습: 중복(redundancy)을 줄이고 노이즈를 억제 → 더 안정적인 표현
Clustering
잠재 특징을 기반으로 클러스터링 지원
Visualization
저차원 임베딩으로 데이터 시각화
Anomaly Detection
재구성 오차로 이상치 탐지
02 Autoencoder as a Compression System Slide 3/11
Autoencoder 구조 다이어그램 SVG
3가지 핵심 구성요소
  • Encoder fθ: 입력 X → 잠재 표현 Z 매핑
  • Decoder gφ: 잠재 표현 Z → 근사 재구성 X̂
  • Bottleneck: 잠재 코드 제약, 정보 흐름 제한
Bottleneck의 중요성
  • 입력을 더 압축된 형태로 표현하도록 강제
  • Z를 통과한 정보만 재구성에 사용 가능
  • 모든 세부사항 암기 대신 두드러진 구조 보존 유도
  • Autoencoder = 손실 압축(lossy compression) 형태
파이프라인 표기
X → Z → X̂    (f_θ: encoder, g_φ: decoder)
Z = f_θ(X) ∈ ℝᵏ,   X̂ = g_φ(Z) ∈ ℝᵈ
03 Recall: Entropy Slide 4/11
엔트로피 H(X) — 불확실성의 양
  • X가 얼마나 불확실하고 예측 불가능한지 정량화
  • 높은 엔트로피 → 소스를 기술하는 데 더 많은 정보 필요
Shannon Entropy
H(X) = −Σ p(x) log p(x)
조건부 엔트로피 H(X|Z) — 잔여 불확실성
  • Z를 관측한 후 X의 남은 불확실성 측정
  • Z가 X에 대해 매우 유익하면 H(X|Z)는 작음
Conditional Entropy
H(X|Z) = −Σ p(x,z) log p(x|z)
엔트로피 vs 확률 분포
AE에서의 의미
잠재 코드 Z는 X를 재구성하는 데 도움이 되는 정보를 포착해야 함. 유용한 표현은 제한된 용량 하에서 입력의 불확실성을 감소시킨다.
04 KL Divergence & Mutual Information Slide 5/11
KL Divergence D_KL(P‖Q)
  • 두 분포 P, Q 간의 차이를 측정
  • 비대칭: D_KL(P‖Q) ≠ D_KL(Q‖P)
  • P = Q일 때만 0, 항상 ≥ 0
D_KL(P‖Q) = Σ p(x) log [p(x)/q(x)] ≥ 0
Mutual Information I(X;Z)
  • 두 확률변수가 공유하는 정보의 양 측정
  • X, Z가 독립이면 I(X;Z) = 0
  • 클수록 Z가 X에 대해 더 유익
  • Z를 알면 X의 불확실성이 얼마나 줄어드는지 측정
I(X;Z) = H(X) − H(X|Z) = H(Z) − H(Z|X) = D_KL(p(x,z) ‖ p(x)p(z)) ≥ 0
Mutual Information — 정보 관계 다이어그램
AE에서의 Trade-off
Z는 X를 재구성하는 데 필요한 정보를 충분히 보존해야 하지만, 너무 많은 정보를 보존하면 의미 있는 압축 없이 trivial copying으로 귀결될 수 있다.
05 Data Processing Inequality Slide 6/11
데이터 처리 부등식 (AE 파이프라인 X → Z → X̂)
I(X; X̂) ≤ I(X; Z) ≤ H(X)
두 가지 핵심 해석
I(X;Z) ≤ H(X)
잠재 코드는 입력 자체보다 X에 대해 더 많은 정보를 담을 수 없다 → 인코더는 정보를 창조하지 못함
I(X;X̂) ≤ I(X;Z)
디코더는 Z에 없는 정보를 복원할 수 없다 → 인코더가 버린 정보는 하류(downstream)에서 재창조 불가
마르코프 체인과 정보 감소 흐름
표현 학습의 목표
Z = f_θ(X)는 제한된 잠재 용량 하에서 최대한 유용한 정보를 보존해야 한다. 더 작은 bottleneck은 더 강한 압축 압력을 만들며, 핵심 과제는 구조 보존에 필요한 중복성을 제거하는 것이다.
06 Dimensionality Reduction & Information Preservation Slide 7/11
일반 설정
  • 고전적 차원 축소: k ≪ d (k가 d보다 훨씬 작음)
  • Z는 입력의 더 낮은 용량 표현
f: ℝᵈ → ℝᵏ,   Z = f(X)
① Informative
I(X;Z)가 커야 함
입력에 대한 충분한 정보 보유
② Compact
Z는 제한된 용량 사용
k가 작을수록 더 압축
③ Useful (Task)
I(Z;Y)가 커야 함
하류 태스크 변수 Y 예측 지원
Compactness vs Utility Trade-off
07 Autoencoder Architecture Slide 8–9/11
재구성 손실 — MSE
ℒ_rec = E_p_data(x) [‖X − X̂‖²]
  • 평균 제곱 오차 (연속형 입력에 적합)
  • 정보이론적 관점: 왜곡(distortion) 척도
재구성 손실 — Binary Cross-Entropy
ℒ_rec = −E[X log X̂ + (1−X) log(1−X̂)]
  • 베르누이 가정 (이진/확률형 입력)
  • 확률론적 해석: 조건부 우도 최대화
  • ℒ_rec ∝ −E_p(x) [log p_φ(x|z)]
확률론적 & 정보이론적 해석

디코더가 조건부 분포 p_φ(x|z)를 정의하면, 재구성 학습은 조건부 우도 최대화로 볼 수 있음:

ℒ_rec ∝ −E_p(x) [log p_φ(x|z)]
  • 재구성 손실 최소화 → Z가 X 재구성에 유용한 정보를 보존하도록 유도
  • bottleneck 제약 하에서: 덜 유용한 변동은 버리고 중요 구조 유지
08 Capacity and Regularization Slide 10/11
유형 조건 특징 문제점
Undercomplete AE k < d 잠재 코드 차원이 낮아 명시적 압축 발생 과도한 압축 시 유용한 정보 손실
Overcomplete AE k ≥ d 차원만으로는 압축 강제 불가 충분한 용량이 있으면 항등 매핑 f_θ ≈ g_φ⁻¹ 학습 위험
Overcomplete AE의 실패 원인
  • 충분한 용량이 있으면 네트워크가 항등 매핑으로 수렴 가능
  • 정보이론적으로: I(X;Z) → H(X), 의미 있는 압축 거의 없음
  • 따라서 추가적인 정규화(regularization)가 필요

09 Information Bottleneck (IB) Principle Slide 11/11
IB 목적함수 (Tishby et al., 2000)

입력 X, 타깃 Y, 표현 Z에 대해 Y 예측에 관련된 정보를 보존하면서 최대한 압축된 표현을 찾는 것이 목표

IB Objective
min_{p(z|x)} I(X;Z) − β·I(Z;Y)
두 항의 의미
  • I(X;Z): 표현 복잡도 / 코딩 레이트 → 최소화
  • I(Z;Y): 태스크 관련 정보 → 최대화
  • β: 압축과 예측 간 trade-off 파라미터
상한이 존재하는 이유
  • Z가 X에서 유도되면 Y ↔ Z ↔ X 마르코프 체인 성립
  • 데이터 처리 부등식에 의해: I(Z;Y) ≤ I(X;Y)
  • 어떤 표현도 원래 입력 X보다 Y에 대해 더 많은 정보를 담을 수 없음
